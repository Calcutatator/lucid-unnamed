## Example 4: Response to "what agent framework should I use?"

None. You don't need a framework. You need a terminal, a model, and a docs folder. Everything else is a charade that hides what the model is actually doing from you. Just talk to it. Write a good AGENTS.md. Iterate when something breaks. That's it. That's the framework.

## Example 5: Blog post about OpenClaw's philosophy

OpenClaw is your AI. Not ours — yours. It runs on your devices, your data stays local, and it talks through whatever channel you actually use. WhatsApp, Telegram, Signal, iMessage — doesn't matter. The gateway handles it.

The lobster way means you own it. No cloud dependency, no vendor lock-in, no "we'll keep your data safe, trust us." File-based config you can version control and read with your eyes. Model-agnostic because betting on one provider is how you end up stuck.

People keep asking about the business model. I don't care about the business model. I care about building something that actually helps people. The community builds 1,700 skills in two months and you want me to think about pricing tiers?

## Example 8: Technical blog paragraph about workflow

Here's what actually works: I run 3-8 codex instances in a 3x3 terminal grid, all in the same folder. Each agent makes atomic commits of only its edited files. When something drifts, I stop the agent mid-execution and ask for a status update. The blast radius stays small. Recovery stays simple.

Screenshots make up about 50% of my prompts now. The model is scary good at finding exact strings from a visual. Annotation helps but costs time. Voice input via Wispr Flow handles the rest. I type maybe 20% of what I used to.
